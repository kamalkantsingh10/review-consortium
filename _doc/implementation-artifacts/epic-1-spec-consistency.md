# Epic 1 spec consistency pass (2026-10-02)

Cross-spec conflicts fixed in the draft specs 1.2–1.11 and `epic-1-code-map.md`. Spec 1.1 was not changed. Status fields and the listed Open Questions were left as they were. Where an open question is still undecided, downstream specs follow its currently drafted default.

1. **Read-only DB connection.** 1.6 had a `readonly` kwarg, while 1.10/1.11 used `connect_readonly`. Unified on `connect(study_dir, readonly=False)`, defined in 1.6. With `readonly=True` it opens `mode=ro`, never migrates, returns `None` when `board.db` is absent, and raises `board_version_mismatch`. 1.10 and 1.11 reuse it, and the 1.10 task was removed.
2. **TestConfig shape.** 1.2 used `instrument` (singular), `prompt_variant` and nested `session` overrides. 1.5/1.6 used `instruments` (plural), top-level `pairing`/`repeats`, and multi-Instrument Tests. 1.2 now defines `instruments` (list), optional `models` (default: all), `clips`, `practice` and `session` overrides. `prompt_variant` was dropped because 1.6 rotates variants by Repeat (FR17). 1.5 now says `session.pairing`.
3. **Practice clips.** 1.5 put a `practice:` list in the Test YAML, while 1.6 assumed they were declared per Instrument. Unified on the 1.5 location. Each entry is a `PracticeExample(instrument, clips, answer)` and is defined in 1.2. `session.practice_clips` now means the number of examples per Instrument; 1.5 checks it with a new `bad_practice` error, which also replaces `bad_pairing` for "Practice as target". The 1.5 media check, the 1.6 render and the 1.6 design note now pick the Practice examples by the Trial's Instrument.
4. **Persona loading.** 1.6 read the cards directly, and 1.11 regenerated them with `generate_personas`. Both now use `load_personas` (1.3). 1.11 still checks `render_card` against the stored cards (`panel_mismatch`). 1.6 renamed `personas_missing` to `panel_missing`, the code 1.3 defines.
5. **Duplicate error code.** 1.6 used `test_not_found` where 1.10 and 1.11 used `unknown_test`. Unified on `unknown_test`.
6. **Confirmation codes.** 1.7 used `not_confirmed` for both a declined prompt and a non-interactive run. 1.8 used exit 0 with `aborted` for a decline and `confirmation_required` when there is no TTY. Unified: a decline gives `not_confirmed` with exit 1, and no TTY gives `confirmation_required` with exit 1. A matrix row was added to 1.7.
7. **Ledger reservation vs attempt numbering.** 1.8 reserved "before step 1", but the ledger key needs the attempt number that step 1 creates. Now one writer op, `begin_attempt`, checks the ceiling, inserts the ledger row and increments `attempt` in a single transaction. If the reservation is refused, nothing is written. This keeps the 1.9/1.10 rule "every attempt has a request record" true. 1.7, 1.8 and 1.9 were updated.
8. **Retry vs resume.** Under the 1.7 resume rule, a `sent` Trial waiting for a retry that the ceiling blocked would re-collect its old invalid handle. 1.9 now says that if the latest attempt is already recorded `valid = 0`, resume starts a new attempt.
9. **Invalid-rate definition.** Previously 1.9 and 1.10 each had their own formula. It is now defined once, as `core.validate.invalid_rate(counts)` in 1.9. `board.trials.invalid_rates` and 1.10's rows call it, and 1.11 uses `invalid_rates`. The 1.11 target is now `thresholds.invalid_rate_max`. The rate stays `invalid ÷ terminal`, the drafted default of the 1.9 open question.
10. **Where 1.9 SQL lives.** 1.9 put `chosen_answer` and `invalid_rates` in `board/db.py`, but the table helpers live elsewhere. They moved to `board/trials.py`, the 1.7 module.
11. **Leak tolerance.** 1.4 added a new `LeakTolerance` (`loudness_lu`, an fps tolerance, code defaults). This conflicted with 1.2's required `thresholds.leak_tolerance` (`duration_s`, `loudness_lufs`; resolution and fps exact). 1.4 now uses the 1.2 model.
12. **`MediaLimits.inline_base64`.** 1.5 added it conditionally. It is now defined in 1.2, and 1.5 uses it.
13. **`StudyConfig.concurrency`.** 1.7 added it ad hoc. It is now defined in 1.2 (default 4), and 1.7 references it.
14. **`max_retries` / `repeats` paths.** 1.9 and 1.8 used `StudyConfig.max_retries`. They now use the effective `session.max_retries` (Test override, else `study.yaml`). 1.6 does the same for `session.repeats`.
15. **Prices shape.** 1.2 had a generic `{rate: decimal}` and 1.8 had no named fields. 1.2 now defines `ModelPrice(input_usd_per_mtok, output_usd_per_mtok)`. 1.8 adds `media_tokens_per_s`, `chars_per_token` and `ModelConfig.fake` additively.
16. **Cost inputs.** `estimate(request, ...)` had no access to Clip durations, because requests carry only `clip_id` and SHA-256. A `clip_seconds` argument (from the `clips` table) was added in 1.8 and in the code map.
17. **Trial fields.** The 1.6 `Trial` had no `test`, `session_id` or `trial_index`, which the 1.7 seed key, 1.7 storage and 1.11 ordering all need. Those fields were added. 1.6 now also uses `core.ids.session_id` (1.4).
18. **Prompt variants.** 1.6 used an index plus "no variants → 0", but 1.2 requires a named `default`. 1.2 now defines `prompt_variants` as an ordered name→text mapping, and 1.6 rotates through the names and stores the name.
19. **1.6 read helpers.** 1.6 had an "add a helper if missing" task. It now points to `board/tests.get_test` (1.5) and `board/clips.list_clips` (1.4).
20. **Write-connection AC (1.7).** The 1.7 AC said "only `board/writer.py` opens a write connection", which contradicts the synchronous `connect` that 1.4/1.5 `push` use. It now applies within `open` only. The 1.8 `set_ceiling` became a writer op.
21. **Paused state.** 1.8 stores the pause per Test (`tests.paused_reason`) and 1.10 shows a study-wide footer. The 1.10 footer now shows paused if any Test has `paused_reason` set. 1.8 names the `tests` table explicitly.
22. **Export Persona columns (1.11).** The rule "scalar attributes only" would have dropped the Big Five traits. Now `big_five` is flattened to `persona_<trait>` and `id` is omitted. The pairwise `A`/`B` → Clip ID mapping is now stated explicitly.
23. **Rater shapes (1.7).** `Handle` is now JSON-serialisable (stored in `attempts.handle`), and `usage` is defined as `{input_tokens, output_tokens}`, which 1.8 relies on.

**Code map:** added `config/schema.py` `export_schemas`, `load_personas`, `PracticeExample`, the StudyConfig/TestConfig field names, `board/{clips,tests,trials,queries}.py` with their tables and migrations, `core/media_limits.py`, the `connect` readonly kwarg, `RaterCall`/`Handle`/usage shapes, `begin_attempt`, the `estimate` signature, `invalid_rate`, the ID formats and a shared error-code list.

**Not resolved / notes:**
- The token budget is still exceeded. By a chars÷4 estimate, 1.6–1.9 are about 1,900–2,200 tokens (they were about 1,850–2,100 before this pass), and the frozen 1.1 is about 1,800. The edits added little, but no trimming was done.
- `session.practice_clips` as "examples per Instrument (exact count)" is a new interpretation, introduced to reconcile the 1.2 field with the 1.5 list. It should be confirmed together with the 1.5 open question.
